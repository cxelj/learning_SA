# Тулы (Tools) агентов

> Инструменты, которые ИИ-агент может вызывать для выполнения действий.

## Что такое тулы

**Тулы (tools)** — функции, которые агент может вызывать, чтобы **воздействовать на мир**: читать файлы, выполнять команды, делать запросы.

```
Без тулов:  агент только «говорит»
С тулом:    агент может реально работать: прочитать код, запустить тест, отредактировать
```

## Примеры тулов (на примере OpenCode)

| Тула | Назначение |
|------|-----------|
| **read** | Прочитать файл (с номерами строк) |
| **write** | Создать/перезаписать файл |
| **edit** | Точечное изменение (old → new) |
| **glob** | Поиск файлов по паттерну |
| **grep** | Поиск по содержимому (регулярки) |
| **bash** | Выполнить команду в терминале |
| **webfetch** | Загрузить содержимое URL |
| **websearch** | Поиск в вебе |
| **task** | Делегирование под-агенту |
| **question** | Задать вопрос пользователю |
| **todowrite** | Ведение списка задач |

## Как агент использует тулы (псевдо-процесс)

```
Агент получил: "Найди функцию calculateTotal и добавь тест"

1. grep("calculateTotal")        → нашёл файл order.ts:42
2. read("order.ts")              → понял логику
3. read("tests/order.test.ts")   → понял стиль тестов
4. write("tests/order.test.ts")  → добавил тест
5. bash("npm test -- order")     → запустил тесты
6. читает вывод → тест прошёл
7. возвращает результат
```

## Виды тулов

| Вид | Читающие | Изменяющие | Опасные |
|-----|----------|-----------|---------|
| Пример | read, glob, grep, webfetch | write, edit, bash(write) | git push, rm -rf, drop table |
| Доступ | Безопасны | Требуют проверки | Требуют подтверждения |

## Permissions (права)

Агент не должен иметь доступ ко всему. Права настраиваются:

```
Tuла          Разрешено
read         │  allow
write        │  allow
bash         │  ask (спрашивать пользователя)   ← опасные команды подтверждаются
edit         │  allow
web          │  deny (запрещено)
```

### Уровни прав

| Уровень | Поведение |
|---------|-----------|
| **allow** | Выполнять без вопросов |
| **ask** | Спрашивать пользователя каждый раз |
| **deny** | Запрещено всегда |
| **allowed rules** | Правила: «разрешено для *.ts, запрещено для .env» |

## Что учитывать при проектировании тулов

1. **Один тул = одна ответственность** (single responsibility)
2. **Идемпотентность** — повторный вызов безопасен
3. **Возврат структурированного результата** (код/ошибка)
4. **Безопасность** — не давать лишнего (например, запрет на git push)
5. **Лимиты** — ограничения на размер результата, длительность

## MCP vs встроенные тулы

| | Встроенные тулы | MCP-тулы |
|---|-----------------|----------|
| Откуда | В клиенте (OpenCode) | Внешний сервер (MCP) |
| Что | Базовые (файлы, bash, web) | Специфичные (БД, системы, сервисы) |
| Расширяемость | Фиксированный набор | Любой сервис может их предоставить |
| Пример | read, write, bash | PostgreSQL connector, Jira API, Slack |

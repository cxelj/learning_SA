# Диаграммы классов (Class Diagrams)

> Показывают **структуру** системы: классы, атрибуты, методы и связи между ними.

## Что показывает Class Diagram

- Классы и их **атрибуты** (данные)
- Классы и их **методы** (поведение)
- **Связи** между классами (наследование, ассоциация, зависимость)
- Модификаторы доступа
- Кратности (один-ко-многим и т.д.)

## Как выглядит класс

```
┌─────────────────────────────┐
│           Order             │ ← Имя класса
├─────────────────────────────┤
│ - id: Long                  │ ← атрибуты
│ - total: BigDecimal         │
│ - status: String            │
├─────────────────────────────┤
│ + getTotal(): BigDecimal    │ ← методы
│ + setStatus(s: String): void│
│ # validate(): boolean       │
└─────────────────────────────┘
```

### Модификаторы доступа

| Символ | Модификатор | Смысл |
|--------|-------------|-------|
| `+` | public | Доступен всем |
| `-` | private | Доступен только внутри класса |
| `#` | protected | Доступен наследникам |
| `~` | package | Доступен в пакете |

### Секции класса
1. **Имя класса** — сверху (в жирном шрифте)
2. **Атрибуты** — середина (`- id: Long`)
3. **Методы** — низ (`+ getStatus(): String`)

## Связи между классами

### 1. Ассоциация (простая связь)

```
┌──────────┐                 ┌──────────┐
│  Order   │────────────────▶│  Payment │
└──────────┘    платит        └──────────┘
```

Один класс **использует/ссылается** на другой.

### 2. Агрегация (слабое владение) — ромб полый

```
┌────────────┐        ◇────────┐
│ Department │ ────────────────│ Employee │
└────────────┘                 └──────────┘
```
Сотрудник может существовать **без** отдела.

### 3. Композиция (сильное владение) — ромб закрашенный

```
┌────────────┐        ◆────────┐
│   House    │ ────────────────│  Room  │
└────────────┘                 └────────┘
```
Комната не существует **без** дома.

### 4. Наследование — треугольник

```
        ┌──────────┐
        │  Animal  │
        └─────△────┘
        ┌─────┼─────┐
   ┌────▼──┐  ┌─────▼──┐
   │ Dog   │  │  Cat   │
   └───────┘  └────────┘
```

### 5. Зависимость — пунктир

```
┌──────────┐ ---------─▶ ┌──────────┐
│ Report   │  создаёт    │  PdfGen  │
└──────────┘             └──────────┘
```

## Кратности (Multiplicity)

```
┌──────────┐              ┌──────────┐
│  User    │ 1       0..* │  Order   │
└──────────┘──────────────└──────────┘
```

| Обозначение | Значение |
|-------------|----------|
| `1` | Ровно один |
| `0..1` | Ноль или один |
| `*` / `0..*` | Много (ноль и более) |
| `1..*` | Один и более |
| `2..5` | От 2 до 5 |

**Читается:** User **1** — Order **0..\*** («у одного пользователя много заказов»).

## Пример: интернет-магазин (красиво и структурно)

```
┌──────────────┐  1       * ┌──────────────┐
│    User      │────────────▶│    Order     │
├──────────────┤             ├──────────────┤
│ - id: Long   │             │ - id: Long   │
│ - name: String│            │ - user_id: Long
│ - email: String│           │ - total: BigDecimal
├──────────────┤             │ - status: OrderStatus
│ + login()    │             ├──────────────┤
│ + logout()   │             │ + calculateTotal()
└──────────────┘             │ + confirm()
                    *        └──────────────┘
                      ┌──────────────┐  *   ┌──────────────┐
                      │   OrderItem  │──────│   Product    │
                      ├──────────────┤      ├──────────────┤
                      │ - quantity   │      │ - name       │
                      │ - price      │      │ - price      │
                      └──────────────┘      └──────────────┘
```

## Mermaid-код для Class Diagram

```
classDiagram
    class User {
        -Long id
        -String name
        -String email
        +login()
        +logout()
    }
    class Order {
        -Long id
        -BigDecimal total
        -String status
        +confirm()
    }
    User "1" --> "0..*" Order : создаёт
```

## Как аналитик использует Class Diagram

1. **Модель данных** — для проектирования БД (классы → таблицы)
2. **Доменная модель** — понять бизнес-сущности
3. **Требования** — показать, какие данные нужны
4. **Коммуникация с разработчиками** — общий язык

## Класс vs ERD

| | Class Diagram | ERD |
|---|---------------|-----|
| Показывает | Классы ООП (с методами) | Таблицы БД (без методов) |
| Уровень | Логический (код) | Физический/логический (данные) |
| Типы связей | ассоциация, наследование, композиция... | 1:1, 1:N, N:M через FK |
| Методы | Есть | Нет |

# HTTP методы

> Протокол HTTP — основа веб-взаимодействий. Методы определяют, **какое действие** выполняется над ресурсом.

## Структура HTTP-запроса

```
POST /api/orders HTTP/1.1          ← метод, путь, версия
Host: api.example.com              ← заголовки
Authorization: Bearer token123
Content-Type: application/json

{ "product": "burger", "qty": 2 }  ← тело запроса
```

## Структура HTTP-ответа

```
HTTP/1.1 201 Created               ← статус-код
Content-Type: application/json
Location: /api/orders/12345

{ "id": 12345, "status": "created" }
```

## Основные методы

| Метод | Назначение | Идемпотентный | Тело запроса | Пример |
|-------|-----------|---------------|--------------|--------|
| **GET** | Получить данные | ✅ Да | Нет | Получить список заказов |
| **POST** | Создать ресурс | ❌ Нет | Да | Создать заказ |
| **PUT** | Обновить ресурс **целиком** | ✅ Да | Да | Заменить заказ полностью |
| **PATCH** | Частично обновить | ❌ Не обязателен | Да | Изменить только статус |
| **DELETE** | Удалить ресурс | ✅ Да | Обычно нет | Удалить заказ |
| **HEAD** | Получить только заголовки | ✅ Да | Нет | Проверить доступность |
| **OPTIONS** | Узнать доступные методы | ✅ Да | Нет | CORS-проверки |

## Идемпотентность (важно!)

**Идемпотентный запрос** — запрос, повторное выполнение которого даёт **тот же результат**, что и первое.

```
DELETE /api/orders/12342   ← первый вызов: удаляет заказ
DELETE /api/orders/12342   ← второй вызов: 404 (ресурс уже удалён) — тот же итог, заказ удалён
```

- **GET, PUT, DELETE** — идемпотентные
- **POST** — НЕ идемпотентный (создаёт новый ресурс каждый раз!)

```
POST /api/orders   ← создаёт заказ #1
POST /api/orders   ← создаёт заказ #2 (дубль!)
```

> ⚠️ Чтобы POST стал безопасным при повторных попытках — используют **Idempotency-Key** (см. модуль 7).

## Коды ответов HTTP

### 2xx — Успех
| Код | Значение | Когда |
|-----|----------|-------|
| 200 | OK | Запрос успешен, данные в ответе |
| 201 | Created | Ресурс создан (после POST) |
| 202 | Accepted | Запрос принят, обработка асинхронная |
| 204 | No Content | Успех, но ответ пустой (после DELETE) |

### 3xx — Перенаправления
| Код | Значение | Когда |
|-----|----------|-------|
| 301 | Moved Permanently | Ресурс переехал навсегда |
| 302 | Found | Временное перенаправление |
| 304 | Not Modified | Данные не менялись (кэш) |

### 4xx — Ошибки клиента
| Код | Значение | Когда |
|-----|----------|-------|
| 400 | Bad Request | Некорректный запрос/валидация |
| 401 | Unauthorized | Нет аутентификации |
| 403 | Forbidden | Нет прав (авторизация не пройдена) |
| 404 | Not Found | Ресурс не найден |
| 409 | Conflict | Конфликт состояния |
| 422 | Unprocessable Entity | Семантическая ошибка (не прошёл валидацию) |
| 429 | Too Many Requests | Превышен лимит запросов |

### 5xx — Ошибки сервера
| Код | Значение | Когда |
|-----|----------|-------|
| 500 | Internal Server Error | Непредвиденная ошибка |
| 502 | Bad Gateway | Проблема у вышестоящего сервиса |
| 503 | Service Unavailable | Сервер не готов (перегрузка, обслуживание) |
| 504 | Gateway Timeout | Таймаут ответа |

## Пример: правильное использование методов

Интернет-магазин:

```
GET    /api/products            → список товаров
GET    /api/products/42         → товар с id=42
POST   /api/orders              → создать новый заказ
PUT    /api/orders/42           → полностью заменить заказ 42
PATCH  /api/orders/42/status    → изменить только статус заказа 42
DELETE /api/orders/42           → удалить заказ 42
GET    /api/orders?status=paid  → фильтрация через query params
```

## Правила для аналитика при проектировании API

1. **Ресурс — существительное**, метод — глагол: `GET /users`, а не `GET /getUsers`
2. **Используйте множественное число** для коллекций: `/orders`, `/users`
3. **Не вкладывайте глаголы в URL**: не `/orders/cancel` — это `POST /orders/{id}/cancel` или `PATCH`
4. **Фильтрация и пагинация** — через query params: `?page=2&limit=20&status=paid`
5. **Возвращайте понятные ошибки**:
```json
{
  "error": {
    "code": "ORDER_NOT_FOUND",
    "message": "Заказ с id=999 не найден",
    "details": "Укажите другой идентификатор"
  }
}
```

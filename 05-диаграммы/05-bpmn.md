# BPMN 2.0 (Business Process Model and Notation)

> Стандарт для моделирования **бизнес-процессов**. Показывает шаги процесса, решения, роли и потоки.

## Что такое BPMN

**BPMN (Business Process Model and Notation)** — графический стандарт (OMG) для описания бизнес-процессов. Версия 2.0 — актуальная.

Понятна и **бизнесу** (заказчику), и **разработчикам** (автоматизация).

## Основные элементы BPMN

### 1. События (Events)

```
(○)   стартовое событие (start)      — начало процесса
(●)   промежуточное                  — шаг процесса
(◉)   конечное событие (end)         — конец процесса
```

### 2. Задачи / активности (Tasks / Activities)

```
┌──────────┐
│  Задача   │  — прямоугольник со скруглёнными углами
│(Задача)   │  — подтипы: user task, service task, script task...
└──────────┘
```

Стандартные типы задач:

| Тип | Значок | Смысл |
|-----|--------|-------|
| User Task | человечек | Выполняет человек |
| Service Task | шестерёнка | Выполняет система/сервис |
| Script Task | листок | Программный скрипт |
| Manual Task | рука | Внешнее ручное действие |

### 3. Шлюзы (Gateways) — развилки

```
◇   эксклюзивный (XOR) — одно из путей
◇+  параллельный (AND) — все пути
◇O  инклюзивный (OR)   — один или несколько
```

```
        ┌──────────────────── 턘 [Товар в наличии?]
        │  да                          │ нет
   ┌────▼────┐                   ┌─────▼──────┐
   │ Отправить│                  │Уведомить клиента
   │заказ     │                   │ (нет на складе)
   └──────────┘                  └────────────┘
```

### 4. Потоки (Flows)

| Элемент | Обозначение | Смысл |
|---------|-------------|-------|
| Sequence flow | сплошная стрелка | Порядок шагов |
| Message flow | пунктир круг → стрелка | Сообщение между участниками |
| Data object | 📄 документ | Данные процесса |
| Association | пунктир | Связь с данными |

### 5. Дорожки и пулы (Lanes and Pools)

```
┌──────────────────────────────────────────────┐
│  POOL: Магазин                               │
│  ┌────────────────────────────────────────┐  │
│  │ LANE: Отдел продаж                     │  │
│  │ (○) → [Получить заказ] → [Проверить]   │  │
│  ├────────────────────────────────────────┤  │
│  │ LANE: Отдел доставки                   │  │
│  │        [Собрать] → [Отправить] → (◉)   │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```

**Pool** — участник процесса (компания/система).
**Lane** — роль внутри участника (отдел, должность).

## Пример BPMN: Оформление заказа в магазине

```
POOL: Покупатель          POOL: Магазин
┌─────────────────────────┐┌────────────────────────────────────────┐
│ (○) Оформить заказ  ────▶ Обмен сообщениями ─▶ (○) Принять заказ   │
│                         ││  │                                       │
│                         ││  ◇ [Оплата подтверждена?]               │
│                         ││  ├─ да ──▶ [Собрать] → [Отправить] →(◉) │
│                         ││  └─ нет ─▶ [Отменить заказ] →(◉)        │
└─────────────────────────┘└────────────────────────────────────────┘
```

## BPMN vs блок-схема vs UML Activity

| | BPMN | Блок-схема | UML Activity |
|---|------|-----------|--------------|
| Цель | Бизнес-процесс, роли, сообщения | Простейший алгоритм | Логика программы |
| Роли/дорожки | ✅ Есть | ❌ | ⚠️ |
| События | Богатый набор | Базовый | Средний |
| Стандарт | OMG 2.0 | Нет | OMG |
| Для кого | Бизнес + разработка | Начальный уровень | Разработка |

## Основные подтипы событий (символы в круге)

| Значок | Событие | Смысл |
|--------|---------|-------|
| ○ | Timer | По времени (через 24 часа, каждый день 8:00) |
| ○✉ | Message | Пришло сообщение |
| ○⚠ | Error | Ошибка |
| ○ | Signal | Сигнал (глобальное уведомление) |
| ○⏱ | Conditional | Если выполнено условие |

Пример с таймером:

```
(○) → [Заказ создан] → (●Timer: 24 часа) → [Проверить оплату]
                                                 │
                                          ◇ [Оплачен?]
                                          ├── да ──► [Подтвердить] → (◉)
                                          └── нет ─► [Отменить] → (◉)
```

## Когда аналитику применять BPMN

✅ Моделирование бизнес-процессов (as-is / to-be)  
✅ Постановка требований для автоматизации  
✅ Согласование процесса с заказчиком  
✅ Документирование процессов («Порядок обработки заказа»)  

**НЕ применять** для описания алгоритмов программы (используйте UML Activity / блок-схему).

## Практическое задание

**Сценарий:** Процесс рассмотрения заявки на возврат товара в интернет-магазине: клиент подаёт заявку → менеджер проверяет → если одобрено — возврат средств, если отклонено — уведомление клиенту.

**Задание:**
1. Опишите BPMN-процесс (текстом или в формате Mermaid) с минимум 5 шагами.
2. Используйте: шлюз (gateway) для ветвления, событие таймера (ожидание ответа клиента до 7 дней), событие прерывания (клиент отменил заявку).
3. Определите роли (Pool/Lane): Клиент, Менеджер, Система оплаты.
4. Чем BPMN-диаграмма отличается от Sequence-диаграммы? Когда какую использовать?

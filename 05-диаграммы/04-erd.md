# ERD диаграммы (Entity-Relationship)

> **Entity-Relationship Diagram** — модель данных: сущности, атрибуты, связи между ними.

## Что показывает ERD

- **Сущности** (таблицы) — что хранится
- **Атрибуты** (колонки) — какие данные
- **Связи** — как таблицы соотносятся
- **Ключи** — PK и FK

## Основные элементы

```
┌────────────────────────────┐        ┌────────────────────────────┐
│          USERS             │        │          ORDERS            │
├────────────────────────────┤        ├────────────────────────────┤
│ PK id: BIGINT              │        │ PK id: BIGINT              │
│    name: VARCHAR(100)      │◄───────┤ FK user_id: BIGINT ──────────
│    email: VARCHAR(255)     │ 1    N │    total: DECIMAL(10,2)    │
│    created_at: TIMESTAMP   │        │    status: VARCHAR(20)     │
└────────────────────────────┘        └────────────────────────────┘
```

| Элемент | Обозначение | Пример |
|---------|-------------|--------|
| **Сущность** | Прямоугольник | USERS, ORDERS |
| **Атрибут** | Поля внутри | id, name, email |
| **PK** | Подчёркнут/помечен | id у каждой таблицы |
| **FK** | Помечен | user_id в orders |
| **Связь** | Линия между таблицами | users 1 ── N orders |

## Нотации ERD

### Crow's Foot (воронья лапка) — самая популярная

```
users 1 ──────────── N orders
      |              ╲ (ногти — "много")
```

| Символ | Значение |
|--------|----------|
| `||` | Ровно один |
| `o|` | Ноль или один |
| `}o` | Ноль и более |
| `}│` / `>│` | Один и более |

### Типы связей в ERD

| Связь | Обозначение | Пример |
|-------|-------------|--------|
| **1 : 1** | `||────||` | user → profile |
| **1 : N** | `||────}|` | user → orders |
| **N : M** | `}│────│{` | students → courses (через таблицу-связку) |

## Обозначение PK / FK

```
┌────────────────────────┐
│ ORDERS                 │
├────────────────────────┤
│ [PK] id                │  ← первичный ключ
│ [FK] user_id           │  ← внешний ключ (ссылается на USERS.id)
│ [UK] order_number      │  ← уникальный ключ
│ total                  │  ← обычный атрибут
└────────────────────────┘
```

## Пример полного ERD

```
┌──────────────┐  1      N ┌──────────────┐  1      N ┌──────────────┐
│    USERS     │───────────│    ORDERS     │───────────│  ORDER_ITEMS │
├──────────────┤           ├──────────────┤           ├──────────────┤
│ PK id        │           │ PK id         │           │ PK id        │
│    name      │           │ FK user_id    │           │ FK order_id  │
│    email     │           │ FK promo_id   │           │ FK product_id│
│    phone     │           │    total      │           │    quantity  │
│    created_at│           │    status     │           │    price     │
└──────────────┘           └──────────────┘           └──────────────┘
                                                    1 │           N
                                       ┌──────────────┘    ┌──────────────┐
                                       │   PRODUCTS        │  PROMOCODES  │
                                       ├──────────────┐    ├──────────────┤
                                       │ PK id        │    │ PK id        │
                                       │    name      │    │    code      │
                                       │    price     │    │    discount  │
                                       │    category  │    │    active    │
                                       └──────────────┘    └──────────────┘
```

## Логическая и физическая модель

| | Логическая ERD | Физическая ERD |
|---|----------------|----------------|
| Что | Бизнес-сущности и связи | Таблицы, колонки, типы |
| Типы данных | Свои (число, текст) | В конкретной БД (BIGINT, VARCHAR) |
| PK/FK | Схематично | Полностью |
| Для кого | Бизнес-заказчик, аналитик | Разработчики БД |

## Mermaid-код для ERD

```
erDiagram
    USERS ||--o{ ORDERS : "делает"
    ORDERS ||--o{ ORDER_ITEMS : "содержит"
    PRODUCTS ||--o{ ORDER_ITEMS : "в"
    PROMOCODES ||--o{ ORDERS : "применяется"

    USERS {
        bigint id PK
        varchar name
        varchar email
        timestamp created_at
    }
    ORDERS {
        bigint id PK
        bigint user_id FK
        decimal total
        varchar status
    }
```

## Правила хорошей ERD

1. **Сущность = существительное**, таблица обычно в множественном числе (`users`, `orders`)
2. **Каждая таблица имеет PK**
3. **FK указывает на чужой PK** (или UNIQUE)
4. **Описывайте кратности** на каждой связи
5. **Не рисуйте лишнего** — только то, что нужно для модели данных
6. **Одинаковые имена PK/FK** в обеих таблицах (user_id и там и там)

## Когда применять ERD

- Проектирование БД перед разработкой
- Документирование существующей схемы
- Описание модели данных в требованиях
- Обсуждение изменений схемы с командой

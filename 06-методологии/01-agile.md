# Agile

> Набор принципов гибкой разработки ПО. Основан на **Agile Manifesto** (2001).

## Agile Manifesto — 4 ценности

| Мы ценим ... | Больше, чем ... |
|--------------|-----------------|
| **Людей и взаимодействие** | процессы и инструменты |
| **Работающий продукт** | исчерпывающую документацию |
| **Сотрудничество с заказчиком** | переговоры по контракту |
| **Готовность к изменениям** | следование плану |

## 12 принципов Agile (краткая версия)

1. **Наивысший приоритет** — удовлетворить заказчика ранней поставкой ценности
2. **Приветствуйте изменения** требований даже в конце разработки
3. **Поставляйте работающий продукт часто** (недели, а не месяцы)
4. **Бизнес и разработчики работают ежедневно**
5. Проекты строятся вокруг **мотивированных людей**
6. **Личное общение** — самый эффективный способ передачи информации
7. **Работающий продукт** — главная мера прогресса
8. **Устойчивый темп** разработки (без выгорания)
9. **Постоянное внимание к качеству** и технике
10. **Простота** — искусство делать достаточно (не больше)
11. **Самоорганизующиеся команды** дают лучшие результаты
12. Команда **регулярно анализирует**, как стать эффективнее, и корректирует

## Waterfall vs Agile

| Критерий | Waterfall (каскад) | Agile |
|----------|--------------------|-------|
| Требования | Всё сразу, в начале | Постепенно, итерациями |
| Изменения | Практически невозможны | Приветствуются |
| Поставки | В конце проекта | Часто (каждый спринт) |
| Заказчик | Дал ТЗ и ушёл | Вовлечён весь проект |
| Риски | Обнаруживаются поздно | Обнаруживаются рано |
| Тестирование | В конце | Непрерывно |
| Когда применять | Чёткие требования, регламенты | Неопределённость, быстрые изменения |
| Примеры сфер | Гос. проекты, безопасность | Веб-приложения, стартапы, продукты |

## Что такое iteration (итерация)

Цикл разработки: **спланировали → сделали → показали → получили фидбек → учитесь**.

```
Итерация 1: [план] [разработка] [демо → фидбек]
Итерация 2: [коррекция] [разработка] [демо → фидбек]
  ...
```

Продукт растёт кольцами: сначала ядро, потом функции.

## Ключевые практики Agile

| Практика | Что это |
|----------|---------|
| **User stories** | Требования в виде «Как [роль], я хочу [действие], чтобы [польза]» |
| **Backlog** | Список задач, упорядоченный по приоритету |
| **Iteration/Daily** | Короткие циклы, ежедневные встречи |
| **Demo/Sprint review** | Демонстрация заказчику результата |
| **Retrospective** | Ретроспектива: что улучшить в процессе |
| **Definition of Done** | Критерии «сделано» (готово = задеплоено, протестировано...) |
| **Estimation** | Оценка сложности (story points, T-shirt sizes) |
| **User Story** | Написать как «Как клиент, я хочу оформить заказ онлайн, чтобы не стоять в очереди» |

## Agile — это НЕ только Scrum

| Фреймворк | Идея |
|-----------|------|
| **Scrum** | Спринты, роли, церемонии |
| **Kanban** | Непрерывный поток задач, визуализация (доска), WIP-лимиты |
| **XP** | Инженерные практики: TDD, парное программирование, CI |
| **Lean** | Бережливое производство: устранять потери (Muda) |
| **SAFe** | Масштабирование Agile на большие организации |

## Роль аналитика в Agile

- Ведёт **бэклог** и пишет **user stories** + критерии приёмки
- Участвует в **планировании спринта** (приоритизация, оценка)
- **Проясняет требования** в процессе разработки
- Переводит **бизнес-потребности** в задачи разработки
- Участвует в **review** (проверяет, что сделано соответствует требованиям)

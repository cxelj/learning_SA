# WebSocket

> Постоянное двустороннее соединение между клиентом и сервером для real-time коммуникации.

## Что такое WebSocket

WebSocket — протокол поверх TCP, который устанавливает **постоянное двухстороннее соединение**. После рукопожатия сервер может **пушить** данные клиенту **без запроса** клиента.

## Как это работает

```
Клиент                           Сервер
   │                                │
   │  HTTP Upgrade запрос           │
   │ ──────────────────────────────►│
   │  101 Switching Protocols       │
   │ ◄───────────────────────────── │
   │                                │
   │  ──── Соединение открыто ────  │
   │  { "type": "chat", ... }       │
   │ ◄───────────────────────────── │  ← сервер ПУШИТ без запроса
   │                                │
   │  { "text": "Привет" }          │
   │ ──────────────────────────────►│  ← клиент шлёт сообщение
   │                                │
   │  ... (соединение живёт) ...    │
```

## REST vs WebSocket

| Критерий | REST | WebSocket |
|----------|------|-----------|
| Соединение | Новое на каждый запрос | Одно постоянное |
| Направление | Клиент → Сервер | Двустороннее |
| Push с сервера | Нет | Да |
| Реалтайм | Нет | Да |
| Задержка | Выше (переустановка соединения) | Минимальная |
| Масштабирование | Проще (stateless) | Сложнее (нужно держать соединения) |
| Применение | Стандартные API | Чаты, уведомления, live-данные |

## Когда применять WebSocket

**Применять:**
- Онлайн-чаты и мессенджеры
- Уведомления в реальном времени
- Биржевые котировки, курсы валют
- Совместная работа (Google Docs, Figma)
- Онлайн-игры (мультиплеер)
- Live-статистика, мониторинг (Dashboards)

**НЕ применять:**
- Обычные запрос/ответ API (оверкилл)
- Если обновления редки (лучше polling) — постоянная коннекция дороже
- Когда не нужен реалтайм вовсе

## Когда WebSocket лучше Polling

| Сценарий | Polling | WebSocket |
|----------|---------|-----------|
| Обновления раз в минуту | ✅ Лучше | ❌ Избыточно |
| Обновления каждую секунду | ⚠️ Нагрузка | ✅ Лучше |
| Сервер сам решает когда слать | ❌ Невозможно | ✅ Лучше |
| Мобильное приложение (батарея) | ⚠️ Съедает батарею | ✅ Экономнее |
| Простое приложение | ✅ Проще | ⚠️ Сложнее инфраструктура |

## Пример клиента (JavaScript)

```javascript
const ws = new WebSocket("wss://api.example.com/ws/chat");

// Подключение установлено
ws.onopen = () => {
    console.log("Соединение открыто");
    ws.send(JSON.stringify({ type: "join", room: "general" }));
};

// Получение сообщения от сервера
ws.onmessage = (event) => {
    const msg = JSON.parse(event.data);
    console.log("Новое сообщение:", msg);
    // отрисовать в UI
};

// Ошибка
ws.onerror = (error) => console.error("Ошибка WebSocket:", error);

// Соединение закрыто
ws.onclose = () => console.log("Соединение закрыто");
```

## Проблемы и их решения

| Проблема | Решение |
|----------|---------|
| Соединение разорвалось | Авто-переподключение (reconnect с backoff) |
| Нет ответа (heartbeat) | Ping/Pong каждые N секунд |
| Масштабирование соединений | Redis Pub/Sub для синхронизации между нодами |
| Сохранность сообщений при отвале | Очередь сообщений (Kafka) + восстановление |

## Практическое задание

**Сценарий:** Вы — аналитик в команде, разрабатывающей API для сервиса бронирования отелей. Заказчик хочет, чтобы клиенты могли: искать отели, бронировать номера, отменять бронирования, оставлять отзывы.

**Задание:**
1. Определите основные ресурсы (сущности) системы.
    - `users, hotels, rooms, bookings, reviews`
2. Опишите, что означает RESTlessness (statelessness) на практике для бронирования.
    - `Сервер не хранит этапы бронирования клиента, этапы хранятся на стороне клиента (в браузере/мобильном приложении). Все данные отправляются на сервер только в момент подтверждения бронирования, проверяется токен пользователя и создается запись в базе данных за один рабочий цикл.`
3. Какие HTTP-коды ответов вы будете использовать для каждого из 4 сценариев?
    - `искать отели - 200, 400, 500, 503`
      `бронировать номера - 201, 400, 409, 500, 504`
      `отменять бронирования - 202, 204, 401, 404, 500`
      `оставлять отзывы - 201, 403, 500`
4. Как вы обеспечите версионирование API при добавлении нового типа бронирования через 6 месяцев?
    - `Через добавление нового не обязательного параметра, изначально - если известно что нужно будет добавить новый тип бронирования в будущем/имеется несколько типов бронирования, если не известно/используется только один тип бронирования - добавить только в тот момент когда это будет необходимо (в сущности bookings) в котором будет передаваться тип бронирования. Если параметр не будет передаваться, по умолчанию будет трактоваться что это "старый/базовый" тип бронирования.`

## Вопросы для самопроверки

1. Какие виды API бывают по протоколу?
    - `REST, gRPC, GraphQL, SOAP, WebSocket`
2. Что такое OpenAPI-спецификация?
    - `Международный стандарт для описания REST API в удобном для человека и компьютера формате Yaml/JSON`
3. Зачем нужно версионирование API?
    - `Для того чтобы не ломать существующих клиентов при добавлении новых обязательных параметров или изменении логики работы API`
4. Чем публичный API отличается от внутреннего?
    - `Публичный - досутпен внешним клиентам и сторонним разработчикам для интеграции с сервисами компании, в связи с чем требует более строгой защиты, документации и контроля верси.`
      `Внутренний - только для внутреннего использвания, для взаимодействия с собственными сервисами компании.`
5. Из каких компонентов состоит хорошая спецификация API?
    - 
    ```
      Ресурсы

      Формат данных

      Документация

    ```

# ИИ-агенты: обзор и Harness Engineering

> Что такое ИИ-агент, как они устроены и что такое Harness Engineering.

## Что такое ИИ-агент

**ИИ-агент** — автономная система на основе LLM, которая не просто генерирует текст, а **выполняет задачи**: читает код, ищет файлы, запускает команды, редактирует, тестирует.

```
ЧАТ-БОТ (обычный LLM):
  Вопрос → ответ текстом
  Не может: выполнить команду, изменить файл, сделать HTTP-запрос

ИИ-АГЕНТ:
  Задача → план → ТУЛЫ (инструменты) → результат → проверка
  Может: прочитать код, запустить тесты, отредактировать файлы
```

## Компоненты ИИ-агента

| Компонент | Что делает |
|-----------|-----------|
| **LLM (мозг)** | Принимает решения, генерирует текст/код |
| **Промпт** | Инструкции, определяющие поведение и роль |
| **Контекст** | Что агент «видит»: файлы, история диалога |
| **Тулы (инструменты)** | Возможности: выполнять команды, читать/писать файлы |
| **Петля агента (agent loop)** | Цикл: думать → действовать → наблюдать результат → снова |
| **Память** | Краткосрочная (диалог) и долгосрочная (файлы, знания) |

## Цикл работы агента (Agent Loop)

```
1. Получить задачу от пользователя
2. Составить модель решения (план)
3. Выбрать инструмент(ы)
4. Выполнить действие (вызвать тул)
5. Наблюдать результат
6. Оценить: задача решена?
   ├── да → выдать результат
   └── нет → вернуться к шагу 3
```

## Типы ИИ-агентов

| Тип | Описание | Пример |
|-----|----------|--------|
| **Кодинг-агенты** | Пишут и редактируют код | OpenCode, Cursor, Copilot |
| **Агенты-исследователи** | Ищут и анализируют информацию | Deep Research |
| **Агенты-планировщики** | Декомпозируют задачи, проектируют | Plan-агенты |
| **Агенты-ревьюеры** | Проверяют код | Reviewer |
| **Агенты-тестировщики** | Пишут и запускают тесты | Tester |
| **RAG-агенты** | Отвечают по базе знаний | Support bots |

## Multi-agent системы

Несколько агентов, каждый со своей ролью, организуются в **процесс**:

```
Пользователь: "Разработай фичу X"
    │
    ▼
┌─────────────┐   план   ┌───────────┐
│ Plan-agent  │─────────►│ Explore   │ (исследует код)
└─────────────┘          └───────────┘
                              │
                              ▼
                    ┌──────────────┐
                    │ Build-agent  │ (пишет код)
                    └──────────────┘
                              │
                              ▼
                    ┌──────────────┐
                    │ Tester-agent │ (тестирует)
                    └──────────────┘
                              │
                              ▼
                    ┌──────────────┐
                    │ Reviewer     │ (ревью)
                    └──────────────┘
```

## Harness Engineering (инженерия «обвязки» агентов)

**Harness Engineering** — дисциплина проектирования **окружения и «обвязки» вокруг агентов**, чтобы они работали надёжно и предсказуемо.

Термин ввёл Jesse Vincent (2025). Это «инженерия упряжи» — harness = упряжь/обвязка.

### Что входит в Harness

| Элемент | Назначение |
|---------|-----------|
| **Инструменты (tools)** | Что агент умеет: bash, файлы, web |
| **Промпты/инструкции** | Правила поведения агента |
| **Контекст** | Какие знания и файлы доступны |
| **Безопасность** | Ограничения действий, permissions |
| **Интерфейс** | Как агент взаимодействует с пользователем |
| **Процесс (pipeline)** | Этапы: исследование → код → тесты → ревью |
| **Петли и валидация** | Проверки результата перед завершением |
| **Память и знания** | База знаний, стили, стандарты проекта |

### Почему это важно

| Без Harness Engineering | С Harness Engineering |
|------------------------|----------------------|
| Агент отвечает «как попадёт» | Предсказуемое поведение |
| Нет доступа к нужным данным | Правильные тулы и контекст |
| Не знает стандартов проекта | Знает AGENTS.md, код-стайл |
| Может натворить бед | Валидация и permissions |
| Только текст | Реально работает в репозитории и выполняет задачи |

### Примеры элементов harness в OpenCode

```
opencode.json            ← конфигурация (модели, MCP, permissions)
.opencode/agents/        ← определения агентов (роли + промпты)
.opencode/skills/        ← скилы (навыки)
AGENTS.md                ← инструкции для агентов по работе с проектом
CLAUDE.md / CONTRIBUTING ← стандарты и правила
```

## Промпт vs Скил vs Тула (кратко)

| Понятие | Что это | Пример |
|---------|---------|--------|
| **Промпт** | Текстовая инструкция | «Ты — системный аналитик. Отвечай по-русски» |
| **Скил** | Набор инструкций + ресурсы для задачи | скил «code-style», «testing», «security» |
| **Тула** | Исполняемое действие | read file, run bash, fetch URL |
| **MCP-сервер** | Внешний сервис инструментов | файловая система, БД, браузер |

**Задание:**

2. Какие 3 инструмента (tools) потребуются агенту для работы? Опишите их функции.
3. Опишите цикл работы агента (perceive → think → act) для одного обращения клиента.
4. Как вы обеспечите, чтобы агент не «галлюцинировал» и не давал некорректные ответы?

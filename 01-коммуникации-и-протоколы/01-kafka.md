# Kafka

> Распределённая платформа для обработки потоковых данных (событий).

## Что такое Kafka

**Apache Kafka** — это распределённый журнал (log) сообщений, работающий по модели **publisher/subscriber**. Производители (producers) **публикуют** сообщения, потребители (consumers) **читают** их.

В отличие от очереди (RabbitMQ), где сообщение после чтения удаляется, в Kafka сообщения **хранятся на диске** и читаются **несколько раз** разными потребителями.

## Ключевые понятия

### Producer (производитель)
Отправляет сообщения в топики.

### Consumer (потребитель)
Читает сообщения из топиков.

### Topic (топик)
Категория сообщений. Например: `orders`, `payments`, `notifications`.

### Partition (партиция)
Топик разбивается на партиции — это позволяет **параллельно** обрабатывать сообщения. Сообщения в партиции упорядочены.

```
Topic "orders" (3 партиции)
┌──────────┐  ┌──────────┐  ┌──────────┐
│ Part 0   │  │ Part 1   │  │ Part 2   │
│ msg 1    │  │ msg 2    │  │ msg 3    │
│ msg 4    │  │ msg 5    │  │ msg 6    │
└──────────┘  └──────────┘  └──────────┘
 Consumers:     Consumers:     Consumers:
 c1, c2         c3            c4, c5
```

### Consumer Group (группа потребителей)
Несколько потребителей объединяются в группу. Каждая партиция читается только одним потребителем из группы — это даёт **масштабирование**.

### Offset (смещение)
Позиция потребителя в партиции — что он уже прочитал.

### Replication (репликация)
Каждая партиция копируется на несколько брокеров — это обеспечивает **отказоустойчивость**.

### Broker (брокер)
Сервер Kafka. Кластер состоит из нескольких брокеров.

## Схема работы

```
        Producer (создал заказ)
              │
              ▼
   ┌──────────────────────┐
   │       Kafka          │
   │   ┌──────────────┐   │
   │   │ Topic: orders│   │
   │   │ [p0][p1][p2] │   │
   │   └──────┬───────┘   │
   └──────────┼───────────┘
              │
     ┌────────┴────────┐
     │                 │
     ▼                 ▼
  Service A        Service B
  (логистика)      (аналитика)
  Consumer Group   Consumer Group
```

## Когда применять Kafka

**Применять:**
- Асинхронное взаимодействие между микросервисами
- Стриминг событий (логи, метрики, пользовательские действия)
- Event sourcing (хранение событий как источника истины)
- Разделение нагрузки (buffer/deceleration)
- Интеграция систем в реальном времени

**НЕ применять:**
- Для синхронного запроса/ответа (используйте REST/gRPC)
- Для малого числа сообщений и простых задач (оверкилл)
- Если нужна строгая гарантия доставки ровно 1 раз (Kafka даёт at-least-once по умолчанию)

## Пример (Python — библиотека confluent-kafka)

```python
# Producer
from confluent_kafka import Producer

producer = Producer({"bootstrap.servers": "localhost:9092"})

def on_delivery(err, msg):
    if err:
        print(f"Ошибка: {err}")
    else:
        print(f"Отправлено в {msg.topic()}[{msg.partition()}]")

producer.produce("orders", key="user-42", value="Бургер и кола", callback=on_delivery)
producer.flush()
```

```python
# Consumer
from confluent_kafka import Consumer

consumer = Consumer({
    "bootstrap.servers": "localhost:9092",
    "group.id": "kitchen-service",
    "auto.offset.reset": "earliest",
})
consumer.subscribe(["orders"])

while True:
    msg = consumer.poll(1.0)
    if msg is None:
        continue
    if msg.error():
        print(f"Ошибка: {msg.error()}")
        continue
    print(f"Получен заказ: {msg.value().decode()}")
```

## Важные концепции для аналитика

1. **At-least-once** — сообщение может быть доставлено повторно → обработчики должны быть **идемпотентными**
2. **Порядок гарантируется** только в пределах партиции
3. **Retention** — срок хранения сообщений в топике (по умолчанию 7 дней)
4. **Dead Letter Queue (DLQ)** — топик для сообщений, которые не удалось обработать

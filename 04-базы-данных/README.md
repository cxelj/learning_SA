## Как выбрать тип БД — сводная схема

```
Нужны ли отношения и JOIN'ы, сложные запросы?
│
├── ДА → РЕЛЯЦИОННАЯ БД
│        PostgreSQL / MySQL / Oracle / SQL Server
│
└── НЕТ → спросите: какие данные?
     ├── Ключ-значение (кэш, сессии) → Redis
     ├── Документы (JSON, гибкая схема) → MongoDB
     ├── Графы (связи между сущностями) → Neo4j
     ├── Wide-column (огромные объёмы, время) → Cassandra, HBase
     └── Полнотекстовый поиск → Elasticsearch
```

4. **Транзакции** — как данные остаются согласованными
5. **NoSQL** — альтернативные модели

## Ключевые термины модуля

| Термин | Определение |
|--------|-------------|
| Таблица | Хранит однотипные сущности (пользователи, заказы) |
| Строка (запись) | Один экземпляр сущности |
| Колонка (поле) | Один атрибут сущности |
| PK | Первичный ключ — уникальный идентификатор строки |
| FK | Внешний ключ — ссылка на PK другой таблицы |
| Индекс | Структура для ускорения поиска |
| Транзакция | Набор операций, выполняемых атомарно |
| ACID | Набор свойств транзакций |

# Модуль 2: Интеграции систем

> Способы, которыми системы обмениваются данными.

## Темы модуля

3. [WebSocket](03-websocket.md) — постоянное двустороннее соединение
4. [Polling vs Pushing](04-polling-vs-pushing.md) — как получать обновления
5. [Callback](05-callback.md) — обратные вызовы

## Сводная таблица

| Стиль | Протокол | Формат данных | Тип | Когда применять |
|-------|----------|---------------|-----|-----------------|
| REST | HTTP/1.1 | JSON/XML | Запрос-ответ | Стандарт для публичных API |
| gRPC | HTTP/2 | Protobuf (бинарный) | Запрос-ответ, стриминг | Внутренние сервисы, высокая производительность |
| WebSocket | TCP (const connection) | JSON/Бинарный | Двусторонний, реалтайм | Чаты, уведомления, live-данные |
| Polling | HTTP | JSON | Клиент инициирует | Простые случаи, нет постоянного соединения |
| Callback | HTTP (как правило) | JSON | Сервер уведомляет | Асинхронные процессы, вебхуки |

## Ключевые решения при выборе интеграции

```
Вопрос: "Нужен ли ответ сразу?"
   ├── ДА ──► Синхронная коммуникация
   │           ├── REST (клиент-сервер, JSON)
   │           └── gRPC (клиент-сервер, бинарный, быстрее)
   │
   ├── НЕТ ──► Асинхронная коммуникация
   │            ├── Kafka / очередь (посредник)
   │            └── Callback / Webhook
   │
   └── Вопрос: "Нужен ли реалтайм?"
        ├── ДА ──► WebSocket (постоянное соединение)
        └── НЕТ ──► Polling (периодические запросы)
```

## Когда что выбирать — практические примеры

| Сценарий | Интеграция | Почему |
|----------|-----------|--------|
| Публичное API для внешних разработчиков | **REST** | Стандарт, документирован, прост |
| Коммуникация микросервисов внутри кластера | **gRPC** | Быстрее, строгие контракты, стриминг |
| Онлайн-чат и уведомления | **WebSocket** | Сервер должен ПУШИТЬ данные без запроса |
| Статус долгого асинхронного задания | **Polling** или **Callback** | REST не поддерживает push |
| Оплата через платёжный шлюз | **Callback/Webhook** | Платёжная система уведомляет о результате |
| Синхронизация отчётов | **Kafka** | Буферизация, replay, независимость сервисов |
| Обновление котировок/курсов | **WebSocket** | Миллисекунды, потоковая передача |

## Тест на выбор интеграции

Дан сценарий — подберите тип интеграции:

1. Мобильное приложение запрашивает профиль пользователя → **REST (синхронно)**
2. Платёжная система уведомляет наш сервис об успешной оплате → **Callback/Webhook**
3. Приложение показывает котировки биржи в реальном времени → **WebSocket**
4. Наш сервис считает статистику по событиям от 20 сервисов → **Kafka (асинхронно)**
5. Внутренний сервис быстро передаёт бинарные данные другому → **gRPC**
6. Простой сайт обновляет список уведомлений каждые 30 сек → **Polling**

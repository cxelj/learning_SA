# Callback (обратный вызов)

> Паттерн асинхронного взаимодействия: сервис **не сразу** возвращает результат, а **вызывает нас** (callback) когда готов.

## Что такое Callback / Webhook

**Callback** — механизм, при котором после завершения длительной операции сервис-исполнитель **сам связывается** с инициатором и передаёт результат.

**Webhook** — реализация callback через HTTP: POST запрос на заранее указанный URL.

## Схема работы

```
СИНХРОННО (REST):
  Клиент ──► POST /api/payment ──► Платёжная система (ждёт ответа 10 сек)
  Клиент ◄── { "status": "approved" } ── Платёжная система

АСИНХРОННО (Callback):
  1. Клиент ──► POST /api/payment + callback_url ──► Платёжная система
  2. Клиент ◄── 202 Accepted                          (запрос принят, не результат!)
  3. Платёжная система обрабатывает платёж (30 сек, 1 мин, 1 час...)
  4. Платёжная система ──► POST /api/our-webhook ──► НАШ СЕРВИС (наш callback_url)
     { "payment_id": 555, "status": "approved" }
```

Ключевое: **инициатор НЕ блокируется** и не опрашивает — сервис сам пришлёт результат.

## Полный цикл webhook

```
┌────────────┐  ① POST /payments (включая callback_url)   ┌────────────────┐
│   НАШ      │──────────────────────────────────────────►│  ПЛАТЁЖНАЯ      │
│   СЕРВИС   │◄──────────────────────────────────────────│  СИСТЕМА        │
└────────────┘          ② 202 Accepted                   └────────────────┘
       ▲                                                          │
       │                                                          │ ③ обработка
       │                                                          ▼
       │         ④ POST /webhooks/payment-result (наш сервер)    ┌────────────────┐
       └──────────────◄──────────────────────────────────────────│  обработала:   │
              (webhook)                                          │  статус платёжа │
                                                                 └────────────────┘
```

## Пример: оплата через платёжный шлюз

**Шаг 1.** Мы отправляем платёж и указываем URL для webhook:

```bash
curl -X POST "https://api.payments.com/v1/payments" \
  -H "Authorization: Bearer secret-token" \
  -d '{
        "amount": 5000,
        "currency": "RUB",
        "callback_url": "https://our-service.com/webhooks/payment-result"
      }'
```

**Шаг 2.** Получаем `202 Accepted` — платёж принят в обработку.

**Шаг 3.** Платёжная система обрабатывает и вызывает наш webhook:

```bash
POST https://our-service.com/webhooks/payment-result
Content-Type: application/json

{
  "payment_id": "pay_123456",
  "status": "approved",
  "amount": 5000,
  "timestamp": "2024-01-15T10:30:00Z"
}
```

**Шаг 4.** Наш сервис обрабатывает событие и подтверждает:

```http
HTTP/1.1 200 OK      ← "получил, спасибо"
```

## Подтверждение получения (ack)

**Важно!** Если не ответить `200 OK`, сервис-отправитель будет **повторять вызов** (retry) через некоторое время.

```
POST /webhooks/payment-result
← 200 OK                     → "принято, больше не шли"
← 500 Internal Error         → "что-то пошло не так — повторю через 5 мин"
← 404 (URL не известен)      → "нет такого endpoint'а"
```

Повторы → обработчик должен быть **идемпотентным** (не создавать двойные записи).

## Callback vs Polling

| Критерий | Callback (push) | Polling (pull) |
|----------|-----------------|----------------|
| Инициатор | Сервер-исполнитель | Клиент |
| Задержка | Минимальная | До периода опроса |
| Нагрузка | Нет пустых запросов | Пустые запросы лишние |
| Сложность | Нужен публичный endpoint | Проще |
| Ошибки отправителя | Retry — нужно идемпотентность | Меньше проблем |
| Когда | События от внешней системы | Редкие изменения, нет доступа извне |

## Когда применять Callback

**Применять:**
- Платёжные системы уведомляют о статусе платежа
- Внешний сервис оповещает о событиях (подписка/отписка)
- Долгие операции (генерация отчёта, обработка файла)
- Интеграция с OAuth провайдерами (redirect_uri)

**НЕ применять:**
- Когда сервис недоступен извне (нет публичного URL)
- Когда нужно отвечать синхронно
- Когда клиент — браузер (нужны другие механизмы)

## Webhook и безопасность

| Угроза | Защита |
|--------|--------|
| Подделка webhook'а | Проверка подписи (signature) в заголовке |
| Повторная доставка | Идемпотентность обработчика |
| Раскрытие данных | HTTPS + секретная подпись |
| Lost events | Журналирование + reconciliation (сверка) периодически |

# UML

> **Unified Modeling Language** — стандартный язык для визуального моделирования систем.

## Что такое UML

UML — набор **нотаций (диаграмм)** для описания различных аспектов системы: структуры, поведения, взаимодействия.

## Классификация диаграмм UML

```
UML 2.x
│
├── СТРУКТУРНЫЕ (структура системы)
│   ├── Class diagram (классы)           ← самая используемая
│   ├── Object diagram (объекты)
│   ├── Package diagram (пакеты)
│   ├── Component diagram (компоненты)
│   ├── Deployment diagram (развёртывание)
│   └── Composite structure
│
├── ПОВЕДЕНЧЕСКИЕ (как система ведёт себя)
│   ├── Use case diagram (прецеденты)    ← часто для требований
│   ├── Activity diagram (деятельность)
│   └── State machine (состояния)
│
└── ВЗАИМОДЕЙСТВИЕ (обмен между объектами)
    ├── Sequence diagram (последовательность)  ← важная для аналитика
    ├── Communication diagram (коммуникация)
    ├── Interaction overview
    └── Timing diagram
```

## Самые полезные для системного аналитика

| Диаграмма | Зачем аналитику | Частота |
|-----------|-----------------|---------|
| **Use Case** | Описать функциональные требования и роли пользователей | ⭐⭐⭐ |
| **Sequence** | Показать порядок взаимодействия в сценарии | ⭐⭐⭐ |
| **Class** | Модель данных/домена | ⭐⭐ |
| **Activity** | Алгоритмы, логика, процессы с ветвлениями | ⭐⭐ |
| **State machine** | Жизненный цикл сущности (заказ: new → paid → shipped) | ⭐⭐ |

## Use Case диаграмма — пример

```
                  ┌────────────────────┐
                  │   Система "Магазин" │
   Покупатель ────►│ ( ○ ) Оформить заказ  │
                  │ ( ○ ) Оплатить     │
                  └────────────────────┘
        ────────  Расширения: оплата через счёт / карту
```

Элементы Use Case:
- **Актёр** (палочка-человек) — роль пользователя/системы
- **Прецедент** (эллипс) — сценарий использования
- **Связи**: include (обязательный подшаг), extend (опциональное расширение), ассоциация актёр→прецедент

## Диаграмма состояний (State Machine) — пример

```
(начало) → [new] ── подтвердить ──► [paid]
                      │                │
                   отменить          доставить
                      ▼                ▼
                   [cancelled]      [shipped] ── доставлено ──► [delivered]
```

Показывает **жизненный цикл** сущности: состояния и переходы между ними.

## Activity диаграмма — пример

```
(начало) → ◇ [Корзина пуста?] ──да──► (конец: показать ошибку)
                        └──нет──► [Оформить заказ] → [Оплата] → [Отправка] → (конец)
                                            ▲
```

Похожа на блок-схему процесса: разветвления, параллельность, действия.

## Нотация связей в UML (общее)

| Связь | Нотация | Смысл |
|-------|---------|-------|
| Ассоциация | `A ─────── B` | Связаны, ссылка |
| Агрегация | `A ◇────── B` | B содержит A (слабое владение, A может жить сам) |
| Композиция | `A ◆────── B` | A часть B (сильное владение, без B нет A) |
| Наследование | `A ─△──── B` | A — наследник B |
| Зависимость | `A -------> B` | A использует B (слабая связь) |

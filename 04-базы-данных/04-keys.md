# Ключи базы данных: PK и FK

> Ключи — фундамент реляционных БД: правильная идентификация записей и связи между таблицами.

## Первичный ключ (Primary Key, PK)

**PK** — колонка (или набор колонок), **уникально идентифицирующая** каждую строку таблицы.

```sql
CREATE TABLE users (
    id BIGSERIAL PRIMARY KEY,     -- PK
    name VARCHAR(100) NOT NULL,
    email VARCHAR(255) UNIQUE
);
```

### Свойства PK

1. **Уникальность** — не может быть двух строк с одинаковым PK
2. **НЕ NULL** — PK обязана быть заполнена
3. **Стабильность** — не должна меняться в течение жизни записи
4. **Неизменность** — переиспользование значений нежелательно

### Виды первичных ключей

| Тип | Пример | Плюсы | Минусы |
|-----|--------|-------|--------|
| **Автоинкремент** (SERIAL) | `1, 2, 3, ...` | Просто, быстро | Проблемы при миграции между БД |
| **UUID** | `550e8400-e29b-41d4-a716-...` | Уникален глобально, без конкурентных блокировок | Больше памяти, медленнее сортировка |
| **Составной PK** | `(order_id, product_id)` | Логично для many-to-many | Громоздкий, сложные ссылки |
| **Натуральный PK** | `email`, ISBN, INN | Осмысленный | Может измениться, не всегда уникален |

> Современная практика: **суррогатный PK** (id BIGSERIAL или UUID) + **UNIQUE ограничение** на натуральные поля (email).

## Внешний ключ (Foreign Key, FK)

**FK** — колонка в таблице, которая **ссылается на PK** другой таблицы. Создаёт связь между таблицами.

```sql
CREATE TABLE orders (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL REFERENCES users(id),  -- FK → users.id
    total DECIMAL(10,2),
    status VARCHAR(20)
);
```

```
┌──────────────┐                 ┌──────────────────┐
│    users     │                 │   orders         │
├──────────────┤                 ├──────────────────┤
│ id (PK) 1    │◄────────────────│ user_id (FK) 1   │
│ name Иван    │  связь через FK │ total      1500   │
└──────────────┘                 └──────────────────┘
```

### Свойства FK

1. **Целостность ссылок** — в `user_id` можно записать только существующий `users.id` (или NULL, если разрешено)
2. **Ограничение на все колонки**: PK, на которую ссылаются, должна быть уникальной (PK/UNIQUE)
3. **Каскадные действия** определяют поведение при удалении родителя

### ON DELETE — что делать при удалении родительской записи

```sql
FOREIGN KEY (user_id) REFERENCES users(id)
    ON DELETE CASCADE     -- удалить и заказы пользователя
ON DELETE RESTRICT       -- не дать удалить пользователя, пока есть заказы
ON DELETE SET NULL       -- обнулить user_id в заказах
ON DELETE SET DEFAULT    -- поставить значение по умолчанию
```

| Действие | Поведение | Когда |
|----------|-----------|-------|
| **CASCADE** | Удаляет связанные записи | Корзина / товар и его характеристики |
| **RESTRICT** | Блокирует удаление родителя | Пользователь с заказами |
| **SET NULL** | Ставит NULL | «Автор удалён, записи остались» |

> ⚠️ CASCADE опасен при случайном удалении — может удалить много связанных данных!

## Виды связей (relationships)

```
1 : 1   ── ОДИН К ОДНОМУ
        users 1 ── 1 profiles
        (пользователь имеет один профиль с доп. данными)

1 : N   ── ОДИН КО МНОГИМ (самая частая)
        users 1 ── N orders
        (один пользователь — много заказов)

N : M   ── МНОГИЕ КО МНОГИМ
        students N ── M courses
        (реализуется через промежуточную таблицу)
```

## N : M — промежуточная таблица

Многие-ко-многим реализуются через **связующую таблицу** с двумя FK:

```sql
CREATE TABLE students (
    id BIGSERIAL PRIMARY KEY
);

CREATE TABLE courses (
    id BIGSERIAL PRIMARY KEY
);

-- Связующая таблица
CREATE TABLE student_courses (
    student_id BIGINT REFERENCES students(id),
    course_id  BIGINT REFERENCES courses(id),
    enrolled_at TIMESTAMP DEFAULT now(),
    PRIMARY KEY (student_id, course_id)   -- составной PK
);
```

```
students ──┐        ┌── courses
           ├─► student_courses ◄─┤
Фёдор ─────┤  Фёдор → Математика  ├──── Математика
           │  Фёдор → Физика      ├──── Физика
Пётр ──────┤  Пётр → Физика       ├──── История
```

## Ограничения (Constraints) — «плюс» к ключам

```sql
CREATE TABLE users (
    id    BIGSERIAL PRIMARY KEY,
    email VARCHAR(255) NOT NULL UNIQUE,      -- NOT NULL + UNIQUE
    age   INT CHECK (age >= 0 AND age < 150), -- CHECK - правило
    name  VARCHAR(100) NOT NULL
);
```

| Ограничение | Что гарантирует |
|-------------|-----------------|
| `PRIMARY KEY` | Уникальность + NOT NULL |
| `UNIQUE` | Уникальность (NULL допустим, несколько) |
| `NOT NULL` | Поле обязательно |
| `CHECK (...)` | Поле проходит условие |
| `FOREIGN KEY` | Ссылка существует |

## Уникальность vs Первичный ключ

| | PRIMARY KEY | UNIQUE |
|---|-------------|--------|
| NULL | Запрещён | Разрешён |
| На таблицу | Один | Много |
| Смысл | Идентификация строки | Ограничение уникальности поля |
| Ссылки | На него ссылаются FK | Тоже может быть целью FK |

**Сценарий:** Вы проектируете БД для интернет-магазина. Сущности: пользователь, товар, категория, заказ, элемент заказа, отзыв, адрес доставки.

**Задание:**
1. Определите PK для каждой таблицы (auto-increment / UUID / natural key). Обоснуйте выбор.
2. Какие FK потребуются для связей: пользователь→заказ, заказ→товар, товар→категория, пользователь→отзыв?
3. Какое ограничение UNIQUE добавите для таблицы `users` (помимо PK)?
4. Если у пользователя может быть несколько адресов доставки — какой тип связи (1:N / M:N) и как вы его реализуете?

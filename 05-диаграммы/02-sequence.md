# Sequence диаграммы (диаграммы последовательности)

> Показывают **порядок взаимодействия** объектов/сервисов во времени для конкретного сценария.

## Что показывает Sequence-диаграмма

- **Кто** участвует (акторы, сервисы, БД)
- **В каком порядке** вызываются операции
- **Кто кому** что передаёт
- **Чем** заканчивается сценарий (успех/ошибка)
- Синхронные и асинхронные вызовы

## Основные элементы

```
┌─────────┐     ┌──────────┐     ┌────────┐
│ Клиент  │     │  Сервис  │     │   БД   │
└────┬────┘     └────┬─────┘     └───┬────┘
     │   lifeline    │               │
     │───────────────│───────────────│──  <- пунктирные линии жизни
     │ 1: POST /order│               │
     │──────────────►│               │
     │               │ 2: SELECT     │
     │               │──────────────►│
     │               │ 3: данные     │
     │               │◄──────────────│
     │ 4: 201 Created│               │
     │◄──────────────│               │
```

### Элементы

| Элемент | Обозначение | Смысл |
|---------|-------------|-------|
| **Актёр/объект** | прямоугольник сверху | Участник |
| **Lifeline** | пунктирная линия вниз | «Жизнь» участника во времени |
| **Сплошная стрелка** | `──────►` | Синхронный вызов (ждём ответ) |
| **Пунктирная стрелка** | `- - - - ►` | Ответ/возврат |
| **Открытая стрелка (незакрашенная)** | `─────►` | Асинхронное сообщение |
| **Activation** | узкий прямоугольник на lifeline | Время, когда объект «работает» |
| **Возврат** | пунктир ← | Возвращаемое значение |
| **Фрагмент alt** | рамка с условием | Ветвление |
| **Фрагмент loop** | рамка | Цикл |
| **Фрагмент par** | рамка | Параллельные вызовы |
| **Destroy** | крестик X | Объект завершил работу |

## Пример: оформление заказа (полный)

```
┌──────────┐   ┌────────────┐   ┌───────────┐   ┌────────────┐
│ Клиент   │   │ API Gateway│   │ OrderSvc  │   │ PaymentSvc │
└────┬─────┘   └─────┬──────┘   └────┬──────┘   └─────┬──────┘
     │ POST /orders  │               │               │
     │──────────────►│               │               │
     │               │ создай заказ  │               │
     │               │──────────────►│               │
     │               │ (req id, sum) │ запроси платёж │
     │               │               │───────────────►│
     │               │               │    200 ok      │
     │               │               │◄───────────────│
     │               │ заказ создан  │               │
     │               │◄──────────────│               │
     │ 201 Created   │               │               │
     │◄──────────────│               │               │
```

## Когда применять Sequence

- Описать **конкретный сценарий** в требованиях («как оплачивается заказ»)
- Показать **взаимодействие сервисов** в архитектуре
- Проиллюстрировать **асинхронный поток** (события, Kafka, webhook)
- Обсудить ошибки и edge cases **до разработки**

## Sequence для асинхронного сценария (Kafka)

```
┌──────────┐    ┌────────┐   ┌──────────┐   ┌──────────┐
│ OrderSvc │    │ Kafka  │   │ PaymentSvc│  │ NotifySvc│
└────┬─────┘    └───┬────┘   └────┬─────┘   └────┬─────┘
     │ pub(orderCreated)          │               │
     │───────────────────────────►│               │
     │                            │ sub           │
     │                            │──────────────►│
     │                            │               │ …обработка
     │                            │   pub(paymentOk) │
     │                            │◄──────────────│
```

## Mermaid-код (вставить в README/Markdown)

```
sequenceDiagram
    participant Client as Клиент
    participant API as API Gateway
    participant Orders as OrderService
    participant Pay as PaymentService

    Client->>API: POST /orders
    API->>Orders: создать заказ
    Orders->>Pay: запросить платёж
    Pay-->>Orders: 200 OK
    Orders-->>API: заказ создан
    API-->>Client: 201 Created
```

## На что обращать внимание (для аналитика)

1. **Точность порядка** — шаги должны совпадать с реальным процессом
2. **Синхронность/асинхронность** — указывайте правильно
3. **Обработка ошибок** — добавляйте фрагменты alt для ошибок:
```
alt статус платёжа = ok
    OrderSvc: подтвердить заказ
else статус = failed
    OrderSvc: отменить заказ
end
```
4. **Таймауты** — что если сервис не ответит

## Практическое задание

**Сценарий:** Пользователь нажимает кнопку «Восстановить пароль». Система должна: отправить email с кодом, пользователь ввести код, система задать новый пароль.

**Задание:** Нарисуйте Sequence-диаграмму (текстом или в формате Mermaid) для этого сценария. Включите:
1. Минимум 3 участника (Пользователь, Фронтенд, Бэкенд, Почтовый сервис).
2. Фрагмент `alt` для двух сценариев: код верный / код неверный.
3. Обработку таймаута (код действителен 5 минут).
